# 第 0 步：先搞清楚这堆名词，不然敲命令会心虚

> **一句话**：先把名词过一遍，后面敲命令就不慌。｜你要做：看表，不用背。

| 名词 | 大白话 |
|---|---|
| **命令行 / 终端 / cmd** | 一个只有文字的窗口。你在里面打字下命令，电脑用文字回你。不用鼠标点 |
| **Python** | 一门编程语言。我们的训练脚本是 Python 写的，所以要装它 |
| **pip** | Python 的"应用商店"。装 Python 时自带。`pip install xxx` 就是下载安装一个工具包 |
| **虚拟环境（venv）** | 一个文件夹，里面装这个项目专用的 Python 和包。好处是不同项目互不干扰，删掉文件夹就等于卸载干净 |
| **CUDA / 驱动** | 显卡驱动是操作系统和显卡之间的翻译。CUDA 是 NVIDIA 给程序调显卡用的接口。版本不匹配是新手第一个大坑 |
| **显存** | 显卡自己的内存，和电脑内存（内存条）不是一回事。我们全程要在 4GB 以内 |
| **模型 / 权重** | 一堆数字文件。Qwen3-0.6B 指"6 亿参数"，文件约 1.2GB |
| **微调 / LoRA** | 微调 = 拿现成模型再教它点新本事。LoRA = 只教一小部分参数（我们只动 0.84%），省显存 |
| **JSON** | 一种文本格式，长得像 `{"键": "值"}`。我们的数据就是这种文件，记事本能打开 |
| **token** | 模型眼里的"字"。一个汉字大约 1 个 token，英文一个单词可能 1~2 个 |

# 第 1 步：学会开命令行、认路

> **一句话**：学会在黑窗口里"进到某个文件夹"。｜你要做：打开 cmd，敲 `cd /d D://ai` 和 `dir`。

**要干什么**：打开那个黑窗口，学会两件事——看自己在哪个文件夹、切到别的文件夹。**这一步不用装任何东西。**

## 操作

**打开命令行（两种方式，任选）**

- 方式一：按 `Win` 键 + `R`，输入 `cmd`，回车。会弹出一个黑窗口。
- 方式二（推荐）：打开文件资源管理器，进入 `D:\ai` 文件夹，在**地址栏**里把路径删掉、输入 `cmd`、回车。这样打开就直接在 `D:\ai`。

**看清你在哪**

窗口里会有一行提示符，例如：

```
C:\Users\你的用户名>
```

`>` 左边就是"你现在所在的文件夹"。刚打开时通常在你的用户目录。

**切盘符和目录**

```
D:
cd \ai
```

第一行切到 D 盘，第二行进入 D 盘根目录下的 ai 文件夹。此时提示符会变成：

```
D:\ai>
```

**看这个文件夹里有什么**

```
dir
```

会列出一堆文件名。

## 你应该看到

输入 `dir` 后有一串文件列表，最后一行类似 `2026/10/29  23:00    <DIR>  docs`。

- 中文显示成乱码：敲一次 `chcp 65001`，回车，之后中文就正常了
- **切记：敲命令时把输入法切成英文**，中文标点会让命令失效

## 这一步做完你有了

一个能用的命令行窗口，知道怎么"进到某个文件夹"。

# 第 2 步：安装 Python

> **一句话**：Python 是所有脚本的运行环境，版本必须锁 3.11。｜你要做：敲 `python --version`，看到 3.11.x。

> 你机器上已经装好了（`D:\ai\venv` 就是用它建的）。这一节是为了你以后换机重装时能照做，以及知道为什么版本必须锁 3.11。

**要干什么**：装 Python 3.11（不要装最新版，见下）。

## 为什么是 3.11

- 3.12 / 3.13 太新，部分 AI 库还没出对应的安装包，你会卡在装包上
- 3.9 太老，有些库直接不支持
- 3.11 是目前最稳的折中

## 操作

1. 浏览器打开 https://www.python.org/downloads/release/python-3119/
2. 拉到页面底部，点 **Windows installer (64-bit)**，下载 `python-3.11.9-amd64.exe`
3. 双击运行。**第一个安装界面最下方有两个勾选框，务必勾上 `Add python.exe to PATH`**（这一勾决定你以后能不能直接敲 `python`，没勾就得重装）
4. 点 `Install Now`，等它跑完，点 Close

## 验证

**关掉刚才的命令行窗口，重新开一个**（PATH 变了必须重开，否则读不到）。然后：

```
python --version
```

应该看到 `Python 3.11.x`（3.11 的任何小版本都行）。

本机实际是 **3.11.15**，由 uv 装的（在 `D://ai//uv-python//` 下），不是官网安装包；版本号对不上是正常的，只要大版本是 3.11。

再试：

```
pip --version
```

应该看到类似 `pip 24.x from D:\ai\venv\...`（如果你还没建虚拟环境，会显示在 Python 安装目录下，正常）。

## 如果不对怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| `'python' 不是内部或外部命令` | 装的时候没勾 Add to PATH | 重新运行安装包 → Modify → 勾上 Add to PATH；或者重装 |
| 提示的是 `Python 3.13.x` | 电脑里原来装过别的版本 | 用 `py -3.11 --version` 指定版本；或者卸掉新版 |
| `'pip' 不是内部或外部命令` | 同上 | 用 `python -m pip --version` 代替，功能一样 |

## 这一步做完你有了

一个能跑的 Python 3.11。

# 第 3 步：建虚拟环境（以后每个项目都要做）

> **一句话**：虚拟环境是给这个项目单独的房间。｜你要做：确认提示符前面有 `(venv)`。

> 你机器上已经有 `D:\ai\venv` 了。这一节重点看两件事：怎么看自己有没有激活成功、忘了激活会出什么错。

**要干什么**：给这个项目单独造一个"房间"，以后所有包装在这个房间里。

## 为什么要这么做

如果你以后做第二个项目，它可能需要另一个版本的库。全装在系统里会互相打架，而且卸载时删不干净。虚拟环境就是"一个文件夹 = 一套独立的 Python"。

## 操作

```
cd /d D:\ai
python -m venv venv
```

第二条命令会跑十几秒，没有任何输出（这是正常的，没输出就是成功）。

然后**激活**它：

```
venv\Scripts\activate
```

## 你应该看到

提示符前面多了一对括号：

```
(venv) D:\ai>
```

看到 `(venv)` 就说明你现在在这个"房间"里，之后 `pip install` 装的东西都只进这里。

## 如果不对怎么办

- 提示 `无法加载文件 ... 因为在此系统上禁止运行脚本`：改用 `venv\Scripts\activate.bat`（带后缀），或者先跑一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 再试
- 提示 `系统找不到指定的路径`：说明上一步 `python -m venv venv` 没成功，检查 Python 是否装好

## 三个必须记住的规矩

1. **每次新开命令行窗口，都要重新激活**：`cd /d D:\ai` 然后 `venv\Scripts\activate`。忘了激活，装的包就跑偏了
2. 怎么确认自己在环境里：提示符有 `(venv)`；或者敲 `where python`，第一行应该是 `D:\ai\venv\Scripts\python.exe`
3. 想退出环境：`deactivate`

## 这一步做完你有了

一个只属于这个项目的 Python 房间，位置在 `D:\ai\venv`。

# 第 4 步：认清你的显卡，搞懂 CUDA 版本

> **一句话**：显卡驱动的 CUDA 版本决定你能装哪个 PyTorch。｜你要做：跑 `nvidia-smi`，读出驱动版本和 CUDA 上限。

**要干什么**：查清楚"我的显卡能不能训、能装哪个版本的 PyTorch"。**这一步全是查看，不装东西。**

## 操作

```
nvidia-smi
```

## 你应该看到

一张表格，重点看四行（下面是示意，你的温度、功耗、进程会不同）：

```
+-----------------------------------------------------------------------------+
| NVIDIA-SMI 457.49       Driver Version: 457.49       CUDA Version: 11.1     |
|-------------------------------+----------------------+----------------------+
|   0  GeForce GTX 1650   WDDM  | 00000000:01:00.0 Off |                  N/A |
| N/A   50C    P8    10W /  N/A |    134MiB /  4096MiB |      0%      Default |
+-------------------------------+----------------------+----------------------+
```

- **Driver Version: 457.49** —— 驱动版本
- **CUDA Version: 11.1** —— **注意：这不是你已经装了 CUDA 11.1，而是"你的驱动最高只支持到 11.1"**。这是新手最大的误解
- **4096MiB** —— 显存 4GB，我们所有的"能不能跑"都由这个数决定
- 最下面那块是当前哪些程序在用显卡

## 怎么用这个数字选 PyTorch

装 PyTorch 必须选"不超过驱动上限"的 CUDA 版本，否则一跑就报 `CUDA driver version is insufficient`。

| 驱动报的 CUDA 版本 | 能装的 PyTorch | 安装命令里的后缀 |
|---|---|---|
| 11.1 ~ 11.7 | 最高 cu118 | `--index-url https://download.pytorch.org/whl/cu118` |
| 11.8 ~ 12.0 | 可以 cu121 | `.../whl/cu121` |
| 12.1 以上 | cu124 或更新 | `.../whl/cu124` |

我们的 1650 是 457.49 驱动（上限 11.1），所以只能装 **cu118** 版的 PyTorch，而且版本不能太新（我们用 2.7.1）。

## 顺便查"算力"

驱动界面看不到这个，要用 Python 查（装完 PyTorch 之后才能查，先记着）：

```python
torch.cuda.get_device_capability(0)
```

返回 `(7, 5)` 表示算力 7.5，属于 Turing 架构。**Turing 不支持 bfloat16**，所以后面所有地方都用 `float16`。

## 如果不对怎么办

- 提示 `'nvidia-smi' 不是内部或外部命令`：显卡驱动没装，或者不是 NVIDIA 显卡。先去 NVIDIA 官网装驱动
- 完全看不到 NVIDIA 字样，只有 Intel/AMD：你的电脑没有 NVIDIA 独显，只能 CPU 训练，0.6B 模型训一轮要好几天，不建议

## 这一步做完你有了

一个明确的答案："我该装哪个版本的 PyTorch"。

## 验证（必做，别跳过）

```
python -c "import torch; print('cuda可用:', torch.cuda.is_available()); print('显卡:', torch.cuda.get_device_name(0)); print('算力:', torch.cuda.get_device_capability(0)); print('显存GB:', round(torch.cuda.get_device_properties(0).total_memory/1024**3,1))"
```

## 如果不对怎么办

|---|---|---|

# 第 8 步：认一遍你电脑上的文件

# 第 9 步：打开数据看一眼（别跳过）

> **一句话**：数据就是"题目 + 材料 + 标准答案"的小卡片。｜你要做：打开一个 json，数一下条数。

**要干什么**：搞懂你要喂给模型的东西长什么样。这一步很多人跳过，然后后面所有报错都看不懂。

## 操作

用记事本打开 `D:\ai\data\fincuge\emotion_train.json`。它会是一行很长很长的文本，开头长这样：

```json
[{"instruction": "判断以下句子的情感属性。", "input": "该公司一季度净利润同比增长三成。", "output": "积极"}, {"instruction": "...", ...}]
```

把它理解为很多个"题目 + 材料 + 标准答案"：

| 字段 | 含义 | 举例 |
|---|---|---|
| `instruction` | 题目要求 | "判断以下句子的情感属性。" |
| `input` | 材料 | "该公司一季度净利润同比增长三成。" |
| `output` | 标准答案 | "积极" |

**为什么答案是"积极"这样的文字，而不是 0/1/2**：因为我们把一切任务都转成"文本进、文本出"，模型只学怎么续写文字。

# 第 10 步：先用 30 条数据跑通（关键一步）

> **一句话**：先用 30 条验证整条管线通不通。｜你要做：跑那条命令，2 分钟，看五段输出。

**要干什么**：花 2 分钟验证整条管线（读数据 → 加载模型 → 训练 → 存盘）是通的。**千万别一上来跑全量，那样错了会浪费 3 小时。**

## 操作

确认提示符是 `(venv) D:\ai>`，然后：

```
python train_sft.py --data_path data/fincuge/emotion_train.json --num_samples 30 --seq_len 128 --batch_size 2 --grad_accum 1 --epochs 1 --fast_loss 1 --out out/smoke
```

这条命令的意思是：只用 30 条数据、训练 1 轮、把结果存到 `out/smoke`（当练习，跑完就删）。

## 你应该看到（按顺序五段）

```
==============================================================
  device = GeForce GTX 1650
  显存   = 4.0 GB
==============================================================
[1/5] 加载模型 D:/ai/models/Qwen3-0.6B
Loading weights: 100%|...| 311/311
trainable params: 5,046,272 || all params: 601,096,192 || trainable%: 0.8395
[2/5] 加载数据 ...，取 30 条
      切分：训练 27 条 / 验证 3 条
[3/5] 每个 epoch 14 个 batch，共 14 次参数更新
[4/5] 开始训练
      [自检] 拿到梯度的参数 392/392，梯度范数和 xxx
[5/5] 完成。adapter 存到 out/smoke
```

**逐行解释**：

- `trainable params: 5,046,272 ... 0.8395%`：6 亿个参数里只有 504 万个在训练，其余冻结。这是 LoRA 的本质，也是 4GB 能跑的原因
- `[自检] 拿到梯度的参数 392/392`：检查 392 个可训练矩阵是不是都收到了梯度。**不是 392/392 就说明训练链路断了**，后面再怎么跑都是白跑
- `共 14 次参数更新`：不是 14 条数据，是 14 次"看一批、调一次"

## 如果不对怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| `CUDA out of memory` | 显存不够 | 把 `--seq_len 128` 改成 64，或 `--batch_size 1` |
| `找不到 data/fincuge/...` | 不在项目目录 | 先 `cd /d D:\ai` |
| 自检显示 `120/392` 之类 | 部分层没挂上 | 别继续，把完整报错发出来 |
| 卡在 `Loading weights` 很久 | 第一次加载慢 | 等 1 分钟，还不动说明模型文件不全 |

# 第 11 步：跑全量训练

> **一句话**：全量训练，一次 3 小时。｜你要做：挑一个任务跑起来，或先读懂参数表。

## 操作

```
python train_sft.py --data_path data/fincuge/emotion_train.json --num_samples 16157 --seq_len 128 --batch_size 2 --grad_accum 4 --epochs 1 --fast_loss 1 --out out/adapter-emotion
```

跑起来后**别关窗口**。4GB 卡上大约 2 小时 50 分。

## 每个参数是什么意思

| 参数 | 大白话 | 我们的取值与原因 |
|---|---|---|
| `--data_path` | 用哪份数据 | 换成 `entity_train.json` 就是另一个任务 |
| `--num_samples` | 最多用多少条 | 16157 = 全用 |
| `--seq_len` | 一条数据最多截多长（token） | 128；按数据长度分布定，别乱写 512 |
| `--batch_size` | 一次同时看几条 | 2；显存只够这么多 |
| `--grad_accum` | 攒几次再看总账 | 4；等效于一次看 8 条，弥补 batch 小 |
| `--epochs` | 同一批数据学几遍 | 1；这份数据一轮就够，多轮会背题 |
| `--fast_loss` | 只算答案部分的误差 | 1；不开会多占约 600MB，4GB 卡会爆 |
| `--out` | 结果存哪 | 换名字就能跑不同任务 |

## 你想跑另外两个任务就换这两处

| 任务 | `--data_path` | `--num_samples` | `--seq_len` | 额外参数 |
|---|---|---|---|---|
| 新闻七分类 | `data/fincuge/newscat7_train.json` | 7071 | 512 | — |
| 事件主体抽取 | `data/fincuge/entity_train.json` | 11752 | 320 | `--val_metric entity --val_limit 200` |

## 中途要关机怎么办

训练进程跟着窗口走，关窗口就断了。正确做法是让它继续跑、你人走开；如果真的必须断，脚本每 300 步会自动存一次断点（`out/adapter-emotion_ckpt`），下次用 `--resume` 接上（注意这是"热启动"，优化器状态不保留，loss 会短暂回升，正常）。

## 这一步做完你有了

`out/adapter-emotion`（最后一轮）、`_best`（验证集最好的一轮）、`_ckpt`（中途断点）。

# 第 12 步：看懂训练日志

> **一句话**：学会读那一行日志。｜你要做：对照字段表，找到 loss、显存、剩余时间三处。

每 40 步会打印一行。下面这行是从**实体任务**的日志里摘的（共 1,318 步）：

```
epoch 1/1 | step 440/1318 | loss 0.1936 | lr 1.69e-04 | 峰值显存 1.55G | 已用 67.9min | 剩 135.4min
```

情绪任务数据多（16,157 条，batch 2），步数会大得多，分母约为 7,200，其余字段读法一样。

逐字段翻译：

| 字段 | 意思 | 正常范围 |
|---|---|---|
| `step 440/1318` | 第 440 次参数更新，共 1318 次 | 一直增加直到跑完 |
| `loss 0.1936` | 当前误差。**看趋势不看绝对值** | 从 2.x 开始，很快掉到 0.2~0.4 |
| `lr 1.69e-04` | 学习率。先升后降 | 开头升到 2e-4，结尾接近 0 |
| `峰值显存 1.55G` | 显卡最高占了多少 | 一路不变才对，忽高忽低=有泄漏 |
| `已用 / 剩` | 已花时间 / 预计还需 | 用来决定什么时候回来看 |

## 判断"训练是否正常"的三条

1. **loss 前 100 步就该明显下降**（2.x → 0.5 以下）。一直在 2.x 不动 = 学习率或数据有问题
2. **显存数字全程一条直线**。越跑越高说明有东西没释放
3. **每 40 步的时间差不多**。突然变慢 3 倍，可能是别的程序抢了显卡

## 什么时候可以停

`epoch 1 结束` + `[验证]` 那两行出现之后，脚本会自己退出，不用你操作。

# 第 13 步：评估（训练完才做）

> **一句话**：用四个脚本算分，并看懂置信度分层。｜你要做：跑情绪评估，读准确率和分层那两段。

## 三个任务用三个不同脚本，别用错

| 任务 | 脚本 | 为什么用它 |
|---|---|---|
| 情绪三分类 | `eval_verbalizer.py` | 直接读三个标签的概率，快且稳 |
| 新闻七分类 | `eval_multi.py` | 生成答案后按类别词匹配 |
| 事件主体抽取 | `eval_entity.py` | 生成一句话，从中抽出主体，再和金标比实体 |

## 操作（以情绪为例）

```
python eval_verbalizer.py --limit 0 --adapter out/adapter-emotion --batch 4
```

`--limit 0` 意思是**全部 2020 条都测**。如果你写成 `--limit 120`，它只会分层抽 120 条——那种分数不能对外说（我们吃过这个亏：120 条分层报 70.8%，全量实际是 75.2%）。

> 下面这段输出是**你自己训的这版**（答案保留 15 种句式），所以是 75.2%；仓库 Release 里发的是把答案压成标签词的 Verbalizer 版，76.3%。两者差 1.1 个点，在噪声范围内。

## 你应该看到

```
评估 2020 条  [('积极', 886), ('消极', 574), ('中性', 560)]
  50/2020  78.0%  23s
  ...
==========================================================
  准确率 75.2%  （2020 条，462s，229 ms/条）
==========================================================
  三类 F1：
    积极: 精确 0.79  召回 0.89  F1 0.84
    ...
  置信度分层：
    ≥0.9        748 条 (37.0%)  准确率 94.3%
```

## 这些数字怎么读

- **准确率 75.2%**：2020 条里答对的比例
- **三类 F1**：每一类单独的精确率/召回率。中性类 F1 只有 0.60（积极 0.84、消极 0.78），是最大短板
- **置信度分层**：这是最有用的部分。"≥0.9 的那 37% 样本准确率 94.3%" 意味着**你可以只信高置信的那部分**，把剩下 63% 交人工

# 第 14 步：常见错误速查

> **一句话**：报错先查这张表。｜你要做：把这一页收藏，出问题先搜关键词。

| 你看到的报错 | 真实原因 | 怎么修 |
|---|---|---|
| `CUDA out of memory` | 显存不够 | 降 `--batch_size` 到 1，或降 `--seq_len` |
| `Tried to allocate 316 MiB` 且卡在 lm_head | 在算整段序列的输出 | 加 `--fast_loss 1` |
| `CUDA driver version is insufficient` | torch 的 CUDA 版本高于驱动 | 换 cu118 重装 torch |
| `cuda可用: False` | 装成 CPU 版 torch | 卸掉，按 index-url 重装 |
| `bf16` 报错 / loss 变 nan | Turing 卡不支持 bf16 | 全程用 float16（脚本默认已处理） |
| `'python' 不是内部命令` | PATH 没配 / 没激活环境 | 见第 2、3 步 |
| `No module named transformers` | 没激活虚拟环境 | `venv\Scripts\activate` |
| `FileNotFoundError: data/fincuge/...` | 不在项目目录 | `cd /d D:\ai` |
| 训练 loss 一直是 0 | label 全被 mask 掉了 | 跑 `python check_train.py` 看"被监督的 token 数"是否 >0 |
| 评估分数比预期低 5~10 个点 | 训练和评估的提示词不一致 | 两边必须调同一个拼接函数，不能各写一份 |
| 长任务跑一半进程消失 | 被系统或终端回收 | 训练放 tmux/不关窗口；脚本有断点 |
| `PermissionError` 写文件 | 文件被 Excel/记事本占用 | 关掉占用它的程序 |

# 附录 B：你可能会问的问题

**Q：为什么不直接微调更大的模型？**
A：4GB 显存装不下。7B 模型光权重就 14GB。想上大模型要么量化推理（不能训练），要么租云卡。

**Q：LoRA 只训 0.84% 参数，效果能行吗？**
A：我们的实测是能。情绪 48.3% → 76.3%（随仓库发布的是把答案压成标签词的 Verbalizer 版；原答案句式版 75.2%），新闻 26.4% → 89.7%，主体抽取 0.5% → 86.1%。原因是这些任务是"窄任务"，模型本来就会，只是需要教它按固定格式输出。

**Q：为什么只训 1 轮？**
A：这套数据 1 轮就收敛，第 2 轮开始背答案（验证集掉、训练 loss 继续降）。想试多轮必须用验证集判断。

**Q：训练要多久？能不能更快？**
A：情绪 2 小时 50 分，新闻 3 小时，实体 3 小时 10 分（都在 4GB 卡上）。提速只有三条路：降序列长度（按数据 P99 定）、降数据量、换更快的卡。

**Q：一定要 NVIDIA 显卡吗？**
A：训练基本是。AMD/Intel 显卡在 Windows 上跑 PyTorch 训练坑很多；CPU 能跑但慢 50 倍以上。
