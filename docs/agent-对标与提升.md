# 对标成熟方案：这个 agent 还能往哪提升

写于 2026-10-29。先说结论：**我们缺的不是"更强的模型"，是置信度校准、约束解码和回归测试这三件工程活。**

---

## 一、看了四类方案

### 1. 级联决策（Cascaded LMs，NeurIPS 2025）

思路是三层级联：小模型先答 → 置信度不够就交给大模型 → 大模型也没把握就转人工。两个关键结论：

- **验证比重新生成便宜得多**：让大模型"检查小模型的答案"只需要读一个 token 的概率，而重新生成要几十个 token。成本差一个数量级。
- **置信度必须校准**：原始 logits 不是概率，"模型说 0.8" 不等于"八成对"。他们用贝叶斯校准把分数映射成真实正确率，否则转交/拒答的阈值全是瞎定。
- 阈值可以**用人工反馈在线更新**（把系统风险当目标函数做 SGD）。

### 2. SLM 做 agent 的综述（arXiv 2510.03847）

小模型（1~12B）在"schema、API 约束"这类任务上足够，甚至比大模型好——因为目标是**格式和字段的准确**，不是开放生成。它给出四条工程手段：

- guided decoding（XGrammar / Outlines）把输出约束在语法内
- 严格 JSON Schema
- validator-first（先校验再执行）
- 置信度打分 + verifier 汇总

它建议的指标也很实在：**cost per successful task、schema 合法率、可执行调用率、p50/p95 延迟**。

### 3. 路由模式（教材型实现 + 一次真实事故）

标准做法是"便宜分类器 +  specialists"，但有三条纪律：

- 路由输出必须是 **enum 约束**（只能是 `billing` / `support` / `unsure` 之一）
- **必须有 fallback 路由**："没有 unsure 的路由器就是一台误路由机器"
- **每次路由决策都记日志**，误路由样本回流成 few-shot 例子

配套事故：某大模型发布时把实时路由器放在前面，上线当天路由出错，表现"突然变笨"，最后被迫恢复手动选择。结论是：**路由是产品界面的一部分，不能静默**。

### 4. Anthropic《Building Effective Agents》

看完几十个生产实现后的结论：成功的是"简单的、可组合的模式"，不是复杂框架；**只在能测量的地方增加自主性**。

## 二、我们已经做对的四件事

| 做法 | 对应的成熟模式 |
|---|---|
| 校验层（标签合法 / 实体在原文） | validator-first |
| 三档判定 + `no_route` 反问 | router 必须有 unsure |
| 每次调用写一行 trace | 路由/决策日志 |
| 阈值在回归集上按覆盖率-准确率标定 | 比固定阈值更接近级联方案的做法 |

也就是说，骨架是对的，差的是精细度和闭环。

## 三、差距清单（按性价比排序）

### P0 · 几小时就能做，收益可测

1. **置信度校准**
   现在用的是生成 token 概率的几何平均，**没有校准过**。证据：新闻任务 100% 的样本 conf ≥ 0.8，说明这个分数的尺度是偏的。
   做法：在回归集上拟合 isotonic 或 Platt，把 `conf` 映射成 `P(correct)`。
   收益：阈值变得可解释，三个任务之间可比，跨模型迁移也不用重调。

2. **误路由样本集**
   把路由判断错、以及 `no_route` 但用户明显有意图的样本收 30~50 条，做成一个小回归集。改一次关键词跑一次，别靠感觉。

3. **实体任务的候选重排（针对 78% 的错法）**
   我们 203 条错例里 78% 是"原文有多个公司名，挑错了"。与其重训，不如加一个 verifier：把原文里所有疑似机构名抽出来，按"离事件类型词的距离、出现次数、是否为标题主语"排序，如果重排后的 Top1 和模型答案不一致，就降级成 `hint`。
   更进一步是用 outlines 把输出约束成"……主体是 X。"，X 必须来自原文——从生成源头消灭格式和幻觉。

4. **补两个指标**
   `schema 合法率`（输出能按契约解析的比例）和 `每成功一次的成本`。现在我们只有准确率和拒答率，缺"格式失败"和"成本"这两栏。

### P1 · 一两周，需要人工配合

5. **self-consistency**：低置信样本采样 3 次投票，只在约 20% 的请求上触发，平均成本 ×1.4，换准确率。
6. **阈值在线更新**：拒答的样本本来就有人看，把人工结论回流成标签，每周重算一次 θ。这正是级联方案里的"在线学习"。
7. **few-shot 冷启动**：新任务上线时给 3~5 条示例。但注意我们踩过的坑：**改提示词措辞会让准确率掉 10 个点**，所以这类改动必须走 A/B 和回归集，不能凭感觉上线。
8. **批量接口 + 结果缓存**：同一批请求按任务分组，减少 adapter 切换；重复输入直接命中缓存。

### P2 · 架构层面，本地暂时没有大模型，先留口

9. **SLM-default / LLM-fallback**：低置信转云端大模型。当前 4GB 卡上跑不了第二个模型，但接口可以先留出来（`verifier` 钩子）。
10. **回归 CI**：GitHub Actions 上跑 200 条子集（三个任务各取一段），任何 PR 都跑一遍，分数掉了就红。
11. **合规**：输入长度上限、PII 脱敏、trace 保留期限。

## 四、一个反直觉的优先级判断

**先不要做多轮对话、工具调用、记忆。**

理由很直接：我们三个任务的瓶颈都在"选对那一个答案"，不在"多步推理"。在这种任务上加工具和多轮，只会把每一步的错误概率叠起来（这也是我们一开始就禁止技能互相调用串链的原因）。

Anthropic 的结论一样：只在能测量的地方增加自主性。现在能测量的是准确率、覆盖率、延迟，那就先把这三样做扎实。

## 五、可以拿去当验收标准的目标

| 指标 | 现在 | 目标 |
|---|---|---|
| schema 合法率 | 未统计（实体任务多行输出已 0%） | ≥99.5% |
| 自动通过档准确率 | 情绪 94.3% / 新闻 95.4% / 实体 95.1% | 全部 ≥95% |
| 自动通过档覆盖率 | 37% / 79% / 39% | 平均 ≥50% |
| 误答率（高置信但错） | 未单独统计 | <2% |
| p95 延迟 | 分类约 1s、实体约 1.4s | 分类 <1s、实体 <3s |

这五个数一起看才有意义：只盯准确率，最省事的做法是把置信度阈值拉到 0.99，覆盖率掉到个位数——那是自欺。
